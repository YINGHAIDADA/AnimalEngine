# ADR-0041: 本地化与界面字体

- 状态：Accepted
- 日期：2026-10-24
- 背景与问题：界面文字写死在代码里，只有英文；唯一的字体是引擎内置的 3×5 调试字体，只有大写字母、数字和少量标点，显示不了中文，也不在资源里。游戏要以简体中文为默认语言，并能在菜单中切换语言。
- 决策：
  - **界面字体**：`fonts/ui.font.json` + `fonts/ui.png`，由 `tools/scripts/make_font.py` 从 Fusion Pixel Font 12px（等比、简体中文版，SIL OFL 1.1）生成：可打印 ASCII 与 GB2312 的全部符号和汉字中字体有的 7381 个字（缺少的是“鼗、劐”这类罕用字和部分数学符号），外加缺字方框。每个字形放在 12×16 的格子里（基线在第 13 行），描述文件按格子顺序列出字符和各自的前进宽度。字形表 PNG 约 170 KB，资源包中约 180 KB。字体许可证复制到 `assets/package/fonts/`，并汇入 `THIRD_PARTY_NOTICES.txt`（Fusion Pixel 及其字形来源 Ark Pixel、Cubic 11、Galmuri；均未声明保留字体名，可以做子集）。
  - **引擎**：`BitmapFont`（`animal/resources/bitmap_font.h`）解析描述、加载字形表、按 UTF-8 解码（非法字节显示为替换符）、测量宽度、列出缺字；`Renderer2D::drawText(font, ...)` 在屏幕层绘制（一个字体像素 = `overlayScale() × size` 个窗口像素，带一像素阴影），缺字画方框。调试覆盖层与开发信息仍用内置调试字体，不依赖资源。
  - **文本表**：`strings/<语言>.strings.json`（`animal/framework/strings.h`），按键查文本，`{0}`、`{1}` 为参数；当前语言缺的键用英文，英文也没有时显示键名本身（缺失一眼可见）。现有 `zh-Hans`（简体中文）与 `en`（English），各 75 个键：菜单、设置项、动作名称、HUD、地图、结局、提示消息与关卡提示。按键名称（ENTER、ESC、SPACE、手柄按钮）不翻译。
  - **关卡提示**：触发区、开关、能力宝珠的 `message` 属性若是文本表中的键（如 `level.spikes`），显示当前语言的文本；否则按原文显示，所以在 Tiled 里可以直接写中文试效果，定稿后再加键。示例区域与测试数据的提示已改成键。
  - **语言设置**：`settings.json` 的 `language`，默认 `zh-Hans`；设置页新增“语言”项（左右切换，显示语言自己的名字），立即生效。
  - **资源烘焙**：字体描述、文本表用游戏的解析器校验，字形表 PNG 原样入包（不进材质图集）。烘焙时检查：文本表中所有文字、语言名称和按原文显示的关卡提示是否都在字体里——有缺字则烘焙失败并列出码位（用 `make_font.py` 补字）；某语言缺少其他语言有的键是警告（会显示英文）。
- 主要理由：位图字体与现有像素画风格一致，渲染只是精灵批次，不引入字体光栅化库；包含整个 GB2312，编辑关卡和文本时几乎不会遇到缺字；文本表按键组织，加一种语言只需加一个文件并把它列入游戏的语言顺序。
- 验证方式：单元测试（UTF-8 解码与替换、字体描述解析与错误、宽度与缺字、文本表解析与回退、参数替换；测试数据的两种语言键一致、关卡引用的键存在、所有文字都在字体里；烘焙器对缺字报错、对缺键警告）；菜单测试 `menu_language` 像玩家一样把语言切到英文；其余菜单与能力测试不变；渲染回归不受影响（文字在屏幕层）；中英文的标题、设置、图形页、重绑提示、地图、HUD、提示与结局截图检查。
- 代价与风险：12 像素字体比调试字体高一倍多，菜单行距与布局按新字体重新调整；屏幕层文字随窗口整数倍缩放，小窗口下中文笔画仍清晰但占的画面比例更大。字形表纹理约 5.6 MB 显存（RGBA8）。按键名称保持英文。
- 重新评估条件：加入繁体中文、日文等需要 GB2312 以外字符的语言时，扩展 `make_font.py` 的字符集（或按语言分字体）；需要多行排版（长文本、对话）时，在 `BitmapFont` 上加按宽度换行。
