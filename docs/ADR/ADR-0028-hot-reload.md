# ADR-0028: 热重载：着色器、纹理与关卡数据，失败不崩溃

- 状态：Accepted
- 日期：2026-10-23
- 背景与问题：M4 验收要求“纹理 / 着色器热重载，资源重载失败能报错且不崩溃”。此前只有 F9 重读观感预设；渲染 pass 在初始化时创建管线并长期持有句柄，任何重建都会牵动整个渲染器。
- 决策：
  - **着色器在 RHI 层原地替换**：`Device::reloadShader(shader, desc)`。着色器句柄不变，后端重建引用它的所有管线并保持管线句柄不变，绑定组继续有效，所以渲染器与游戏完全不知道发生了重载。前提是阶段与资源绑定不变（`sameBindings`）；编译 / 链接失败或绑定改变时什么都不改、记录原因并返回 false（“restart to apply”）。OpenGL 重新链接 program；Vulkan 由管线保存的描述重建 `VkPipeline`（同一 layout），旧对象延迟销毁。`ValidatingDevice` 只把错误调用计为校验错误，内容错误不算。
  - **加载器按路径登记**：`loadShader` / `loadTexture` 记住路径与句柄；`reloadShaderFile` / `reloadTextureFile` 把文件重新载入所有相关句柄。纹理只支持同尺寸原地更新（`writeTexture`），尺寸变化报错并提示重启。
  - **文件监视**：`devtools::FileWatcher` 跨平台轮询修改时间与大小（不依赖各系统通知 API），文件在一次轮询内保持不变才报告，避免读到编辑器写了一半的文件；忽略隐藏文件与 `.tmp`。开发构建监视源码目录（`assets/source/world`、`assets/source/textures`、`shaders`），找不到源码时监视部署的 `data/`。工具自己写的文件用 `acknowledge()` 排除。
  - **流程**：着色器源文件变化 → 用构建同一个 `animal_shaderc`（路径编译进开发构建，经平台层 `runProcess` 调用，基于 SDL3 进程 API）编译到 `data/shaders/*.ashd`（编译失败不会覆盖旧文件，输出进控制台）→ `reloadShaderFile`。其他文件先复制到部署目录，再按类型重载：纹理；房间 / Tileset（受影响的房间全部重新解析，全成功才替换）；世界布局（按路径重新找回当前 / 起点 / 检查点房间，丢失正在使用的房间则拒绝）；观感、效果、植物预设（用各自解析器校验后替换，`EffectLibrary` / `PlantLibrary::set` 原地替换不使指针失效）；参数表（ADR-0027）；精灵表（ADR-0030）。被拒绝的数据文件会把部署副本恢复为旧版本，保证磁盘上的 `data/` 与正在运行的内容一致；着色器与纹理“需要重启才生效”的新文件保留（它们本身有效）。
  - **反馈**：成功 / 失败都写日志（控制台）并在 HUD 显示 `RELOADED …` / `RELOAD FAILED … - SEE CONSOLE`；打开着的编辑器跟随外部修改，除非有未保存的编辑（此时只警告）。`--deterministic` / `--demo` 下不监视文件，保证可复现运行。
  - **顺带修复**：Vulkan 在两帧之间调用的延迟释放（`defer`）原先挂在“下一帧”的槽上，该槽的 fence 属于更早的一帧，资源可能在仍被最近一帧使用时就被销毁（热重载替换管线时被验证层发现）；现在两帧之间的释放挂在最近提交的那一帧上。
- 主要理由：在 RHI 层替换让热重载对所有上层代码透明，也不需要引入“资源句柄的句柄”；校验在替换之前，是“失败不崩溃、不半途而废”的唯一可靠做法。轮询足够快（几十个文件，每 0.25 s 一次）且没有平台代码。
- 代价与风险：着色器绑定或顶点输入改变需要重启；纹理改尺寸需要重启；新增的配套贴图（如新加 `_e.png`）不会自动挂到材质上；编译着色器会让那一帧卡顿约 0.1 s。游戏逻辑代码不热重载（PROJECT.md 未决问题，暂不做）。
- 验证方式：`AnimalRhiConformance` 在两个后端上检查：用相同代码重载后图像不变、换成反色着色器后改变、换回后逐像素恢复、绑定不同或阶段不同的包被拒绝；单元测试覆盖监视器与加载器的重载 / 失败路径；集成测试（运行中修改源文件）：坏 JSON、着色器语法错误、类型错误的观感、改尺寸的纹理都被拒绝且游戏继续运行，修好后重新载入；房间、世界、纹理、效果、精灵表的正常重载；Vulkan 下零验证错误。
- 重新评估条件：资源数量大到轮询变慢时换用系统通知（FSEvents / ReadDirectoryChangesW，放在平台层）；需要绑定变化的热重载时引入管线重建回调。
