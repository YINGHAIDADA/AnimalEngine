# ADR-0020: GPU 粒子

- 状态：Accepted
- 日期：2026-10-23
- 背景与问题：M3 范围包含 GPU 粒子：CPU 粒子（ADR-0017）适合每个房间几百个，瀑布、水雾、雨这类成千上万的效果需要在 GPU 上模拟。OpenGL 4.1 没有计算着色器，必须有片元着色器路径；结果要两后端逐像素一致、可在关卡数据中配置。
- 决策：
  - **状态纹理**：两对乒乓的 RGBA32F 纹理（128×128 = 16384 个槽位），A = 位置 xy、速度 xy，B = 年龄、寿命、种子、发射器编号；每帧一个全屏 pass（两个颜色附件）读旧的一对、写新的一对。位置需要 32 位浮点（16 位在 300 px 附近精度只有 0.25 px，慢速粒子会停住），为此 RHI 新增 `Format::RGBA32_Float`（只作渲染目标与采样，不混合）。
  - **模拟**（`gpu_particles_update.frag`）：最多 4 个发射器，各占一段连续槽位（数量固定）。重置时每个槽位取一个随机负年龄，在一个寿命内依次出生；年龄超过寿命即在发射器矩形内重生（速度、寿命按范围随机）；运动 = 加速度 + 风（每帧一个风向量 × 响应）+ 阻力；碰到实心 Tile（光照遮挡图）、越过发射器的 `floor` 线或离开画布即死亡，下一步重生。随机数 = 槽位与帧号的整数哈希，不依赖浮点，所以两后端得到相同的粒子。
  - **绘制**（`gpu_particles.vert`）：每个槽位一个实例，6 个顶点的 1×1 像素四边形，顶点着色器用 `texelFetch` 读状态，死亡或样式不符的槽位放到裁剪体外；位置取整到像素。`lit` 样式在材质 pass 末尾写入 G-buffer（平面法线、无自发光），被灯照亮；`glow` 样式在发光 pass 中加色。着色器工具关闭 SPIRV-Cross 的非零 base instance 支持（OpenGL 后端本来就没有 `firstInstance`），`gl_InstanceIndex` 直接对应 `gl_InstanceID`。
  - **接口**：`Renderer2D::setGpuEmitters`（每个房间设置一次，粒子重新开始）、`setGpuParticleStep(模拟时间, 风)`（每帧在 `beginWorld` 前）、`gpuParticleCount()`；计时域 `gpu particles`。
  - **数据**：沿用粒子效果预设（ADR-0017），`"gpu": true` 即走 GPU；GPU 支持数量、速度范围、加速度（取范围中点）、阻力、风响应、寿命、淡入淡出、颜色、样式、碰撞死亡，其余字段不支持。Tiled `emitter` 对象的矩形即发射区域，可选 `count` 覆盖与 `floor`（世界 y，粒子在其下方消失）。游戏中 `floor` 正好落在水池水面上的 GPU 发射器视为注入水池的水流，每步在其宽度内扰动水面。
  - **示例**：烟雾深坑的瀑布——2600 个下落的水滴从右上平台下方落入水池、在水面处消失，1800 个水雾在落点升起、受风吹动；水面持续起波纹；灯具与水晶从两侧照亮水流。
- 主要理由：片元着色器 + 状态纹理是两个后端共同支持的最小方案；固定槽位 + 死亡即重生不需要 GPU 端的分配与计数；整数哈希随机让结果确定、可回放、可做逐像素对比；沿用效果预设与发射器对象，关卡制作方式不变。
- 代价与风险：每个房间最多 4 个 GPU 发射器、共 16384 个粒子；风是每帧一个向量（不随位置变化）；不支持爆发 / 速率 / 每粒子光源；粒子只有 1 像素；没有粒子之间、粒子与水面的交互（瀑布的水面扰动由游戏在 CPU 上近似）。
- 验证方式：effects 测试覆盖 `gpu` 字段；烟雾深坑截图确认水流、水雾、水面波纹与光照；两后端在烟雾深坑第 30 / 240 / 600 帧及演示路线截图逐像素一致，验证层零报错；GPU 计时：示例瀑布（4400 个）模拟约 0.15 ms，接近容量（15800 个）时约 0.21 ms（Vulkan，Release，Apple M2）。
- 重新评估条件：需要随位置变化的风、粒子碰撞反弹、更多发射器 / 更大容量、多像素或精灵粒子，或目标平台有计算着色器时。
