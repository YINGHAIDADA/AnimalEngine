# ADR-0021: 后端无关的 RHI 校验层

- 状态：Accepted
- 日期：2026-10-23
- 背景与问题：两个后端各自做零散的参数检查，覆盖范围和措辞不同：同一个错误在 OpenGL 下可能被静默忽略，在 Vulkan 下才由验证层报出，而 macOS 的 OpenGL 没有调试输出。M2.5 要求抽出两后端共用的参数校验。
- 决策：
  - **装饰器**：`rhi::ValidatingDevice` 实现 `Device` 接口，包住真实后端并转发所有调用，同时记录资源元数据（缓冲大小与用途、纹理尺寸 / 格式 / 用途、着色器绑定表、管线的颜色格式 / 顶点缓冲数 / 每个 set 的绑定签名、绑定组的 set 与引用的资源）。`createDevice` 在 `DeviceDesc::debug`（Debug 构建）时自动套上；Release 没有任何开销。
  - **创建时检查**（不合法时两后端都返回无效句柄、报同样的错）：缓冲大小 / 用途；纹理尺寸范围、格式、用途；着色器绑定超出 4 × 8 或重复；管线的着色器阶段、颜色目标数量与格式、RGBA32F 不可混合、顶点属性引用未声明的缓冲槽或重复的 location、同一绑定在两个阶段中类型不同；绑定组的 set 是否被管线使用、绑定是否恰好覆盖布局、类型、uniform 缓冲用途 / 对齐 / 越界、纹理可采样且有采样器；销毁未知或已销毁的句柄；`writeBuffer` / `writeTexture` 越界；`readTexture` 无效纹理。
  - **提交时检查**（逐条命令）：渲染通道附件是有效渲染目标且尺寸一致；管线颜色格式与附件一致；绑定组 set 匹配、未被销毁；顶点 / 索引缓冲用途正确；每次绘制前管线需要的顶点缓冲槽和每个 set 的绑定组都已绑定且布局一致、`drawIndexed` 有索引缓冲、`firstInstance` 符合能力；绑定组采样的纹理不是当前通道的附件（反馈回路）、引用的资源未被销毁。通道结构、绘制前已设置管线、计时域成对已由 `CommandList` 在录制时断言，不重复检查。
  - **报告**：每个问题以 `RHI validation:` 前缀记日志，保留前 100 条，退出时打印总数；渲染回归脚本把该总数与 Vulkan 验证层的错误数一起作为失败条件。
  - 后端内部保留最小的防崩溃检查（Release 下没有校验层）。
- 主要理由：同一套规则与措辞适用于两个后端，OpenGL 下也能发现原本只有 Vulkan 验证层才报的问题；装饰器不改动后端代码，可以用不需要 GPU 的假设备做单元测试。
- 代价与风险：Debug 构建每次提交多一次命令遍历与若干 map 查找（相对 GPU 工作可忽略）；不检查着色器内部（例如顶点属性类型与着色器输入是否匹配），也不跟踪纹理内容是否已初始化。
- 验证方式：rhi_validation 测试用不做任何事的 `NullDevice` 覆盖正确用法零报错、缺少顶点缓冲 / 绑定组、附件格式不符、反馈回路、绑定组与布局不符 / 未对齐、使用已销毁资源与重复销毁、各类非法描述；示例游戏全部渲染回归场景在两个后端下 RHI 校验零报错。
- 重新评估条件：需要检查着色器接口匹配、资源状态 / 初始化跟踪，或校验开销在 Debug 下变得明显时。
