# ADR-0011: 玩法要素与存档

- 状态：Accepted
- 日期：2026-10-23
- 背景与问题：M1b 的最后一步要让测试世界成为一个可玩的小切片：房间里有可以拾取的东西、会伤人的东西、给玩家提示的区域，进度在退出后保留。需要决定这些要素放在框架还是游戏里、在 Tiled 中如何表达，以及存档的格式与写入时机。
- 决策：
  - **分层**：框架提供与具体游戏无关的积木——`TriggerSet`（矩形区域，报告“本步进入”，可设为只触发一次）、`stepPatrol`（地面巡逻：撞墙或走到边缘时转身，悬空时下落）、`SaveData` 与 `readSave` / `writeSave`。宝石、甲虫、击退、提示文字、HUD 都在游戏里组合。
  - **Tiled 对象**（补充 ADR-0010 的对象表）：

| 类型 | 形状与位置 | 属性 |
|---|---|---|
| `trigger` | 矩形对象（`x`、`y`、`width`、`height`） | `message`（string，进入时显示；文本表中的键按当前语言显示，否则按原文，见 ADR-0041）、`once`（bool，缺省 true） |
| `gem` | 点对象，宝石中心 | — |
| `crawler` | 点对象，甲虫脚底中心 | — |

  - **宝石身份**：存档标志 `"<房间名>:<对象 id>"`（房间名 = `.tmj` 文件名去扩展名）。Tiled 的对象 id 在地图内唯一且不会复用，因此在 Tiled 中移动或增删其他对象不会改变已收集的宝石。HUD 只统计与世界中现存宝石匹配的标志。
  - **伤害模型**：碰到甲虫不扣血，而是被弹开（远离甲虫 120 px/s、向上 140 px/s），失控 0.25 s、无敌 1 s（角色闪烁），并松开藤蔓。没有死亡状态。
  - **检查点**：进入房间后第一次站稳（着地且不在藤蔓上）的位置。掉出世界时在检查点重生（不再回到起点），并写入存档。
  - **存档文件**：JSON，`{"format":"animal-save","version":1,"room":...,"position":[x,y],"flags":[...]}`，位于 `SDL_GetPrefPath("AnimalEngine","Sandbox")` 下的 `save.json`（macOS：`~/Library/Application Support/AnimalEngine/Sandbox/`；Windows：`%APPDATA%\AnimalEngine\Sandbox\`）。先写 `save.json.tmp` 再重命名覆盖，崩溃不会留下半个文件。格式名或版本不符、字段缺失或类型错误时拒绝加载并记录原因，游戏从头开始，下次保存时覆盖。
  - **写入时机**：拾取宝石、到达检查点时自动保存；启动时读取，存档里的房间不存在时保留宝石、从起点开始。F8 删除存档并回到起点。`--demo` 与 `--deterministic` 不读写存档，保证回放与截图可复现。
- 主要理由：积木留在框架里，可在单元测试中对着 `TileMap` 验证（不需要渲染器）；具体数值和组合是游戏设计，随时会调。用 Tiled 对象 id 作为身份，不需要关卡设计者手工维护键。JSON 可读、便于调试，版本字段为以后迁移留口。
- 代价与风险：房间内的其他状态（甲虫位置、触发器是否已触发）离开后不保留；存档只有一个槽位；甲虫只会沿地面巡逻，不会攀爬或追踪；版本升级时目前只会拒绝旧档，没有迁移代码。
- 验证方式：gameplay 测试覆盖触发器进入 / 只触发一次 / 离开再进入、巡逻在边缘与墙前转身以及无边缘检测时走下平台、存档往返与各类拒绝；`--demo --deterministic` 中角色被长廊的甲虫弹开后仍按原路线到达深坑；手工写入存档后启动，确认恢复到存档房间、已收集的宝石不再出现、HUD 计数正确，伪造的标志不计入；两后端截图逐像素一致。
- 重新评估条件：需要多个存档槽、生命值或死亡、需要保留房间内状态，或存档格式第一次改版时。
