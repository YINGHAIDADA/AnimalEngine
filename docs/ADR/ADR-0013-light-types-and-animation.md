# ADR-0013: 光源类型、动画与灯具

- 状态：Accepted
- 日期：2026-10-23
- 背景与问题：V1 只有点光源；烛光闪烁、水晶脉动写死在游戏代码里，关卡里的 `light` 对象只能设颜色、半径、强度、高度。M2 要让光源类型和动画成为关卡数据，并提供有可见光源的灯具，而不是悬空发光的点。
- 决策：
  - **聚光灯是点光源的参数**，不是新类型：`PointLight::coneAngle`（完整锥角，弧度；0 = 全方向）与 `direction`（单位向量，y 向下）。光照着色器按与锥轴的夹角乘一个因子：锥体外缘五分之一用 smoothstep 过渡，经合成的光照分级后成为一两级色阶，与像素风格一致。顶点多一个 `vec4`（方向 + 外 / 内缘余弦），全方向光源用哨兵值跳过。阴影（ADR-0012）照常生效，所以“从洞顶裂缝照下的天光”= 指向下方的窄聚光灯 + 阴影。
  - **光源动画在框架里**：`LightAnimation { mode, speed, amount }`，`factor(time, phase)` 返回亮度倍数，只依赖时间与相位（确定、无状态，回放可复现）：
    - `flicker`：两个不可通约频率的正弦（13 与 29 rad/s × speed），权重和为 1，用于火焰；
    - `pulse`：`sin(2π · speed · t + phase)`，speed 为每秒周期数，用于水晶等；
    - 倍数保持在 `1 ± amount` 内且不小于 0。
  - **Tiled 属性**（`light` 对象与 `lantern` 对象使用下列名字；光源 Tile 使用加 `light` 前缀、首字母大写的同名属性，如 `lightCone`、`lightAnimation`）：

| 属性 | 类型 | 缺省 | 含义 |
|---|---|---|---|
| `color` | color | 白（灯具为暖黄） | 光的颜色 |
| `radius` | float | 48（灯具 96） | 半径，px |
| `intensity` | float | 1（灯具 1.6） | 强度 |
| `height` | float | 16（灯具 12） | 光源离表面的高度，px |
| `shadows` | bool | true | 是否被遮挡 |
| `cone` | float | 0 | 聚光锥角，度；0 = 全方向 |
| `direction` | float | 90 | 聚光方向，度；0 = 右，90 = 下（顺时针） |
| `animation` | string | none（灯具 flicker） | `none` / `flicker` / `pulse`；未知值警告并忽略 |
| `speed` | float | 1（灯具 0.6） | 动画速度 |
| `amount` | float | 0.15（灯具 0.06） | 亮度摆动幅度 |

  - **灯具对象 `lantern`**：点 = 灯具中心；游戏绘制 8×8 灯具精灵（props 第 3 格），并向上画链条到第一个实心 Tile；光源属性同上，缺省为暖色、轻微闪烁。灯罩的 albedo 刻意偏暗，亮度主要来自自发光，否则会被自己的光照成一团白。
  - 示例世界：水晶 Tile 改为 `pulse` 属性（与原硬编码效果基本相同）；入口房间天花板开一道两格宽的裂缝，放一盏 44° 向下的冷色聚光灯；水晶长廊的展示光源改为灯具（保留原对象 id，ADR-0011 的宝石 id 不受影响）。
- 主要理由：聚光只是点光源加一个角度因子，不需要新的批次、管线或 RHI 功能；动画是纯函数，放在框架便于测试和复用；所有光源（Tile、对象、灯具）在游戏中统一成“`PointLight` + 动画 + 相位”，一条代码路径。
- 代价与风险：聚光灯仍使用以半径为边长的正方形四边形，锥外像素也会执行片元着色器（被锥角因子提前丢弃）；没有面光源 / 线光源；方向光（真正平行的天光）用窄聚光灯近似；灯具不摆动。
- 验证方式：gameplay 测试覆盖动画倍数范围、确定性、相位去相关、脉动周期与峰值、不为负、名称解析；两后端在 `--demo --deterministic` 三个时刻（含天光与灯具）截图逐像素一致，验证层零报错；示例场景 Release 帧时间增加约 0.07 ms。
- 重新评估条件：需要面光源、真正的方向光、灯具摆动 / 被角色撞动，或聚光灯数量多到四边形浪费成为瓶颈时。
