# ADR-0040: 图形设置

- 状态：Accepted
- 日期：2026-10-24
- 背景与问题：光照、阴影、泛光、粒子与 ADR-0039 的补光只能由房间观感决定，或用开发热键（F4 / F7 / F10）临时切换；玩家无法按自己的显示器和机器调整亮度与开销，也不会被记住。
- 决策：
  - 设置菜单新增“图形”页（在“显示”与“按键”之间），六项写入 `settings.json` 的 `graphics` 段（设置文件版本仍为 1，旧文件缺这一段时用默认值）：
    - **亮度** 70%–150%（步长 10%）：乘到观感的曝光上；
    - **阴影** 开 / 关；
    - **间接光与环境遮蔽** 开 / 关：关闭时 `indirect` 与 `ambientOcclusion` 置 0（环境光渐变保留），间接光的降采样与模糊 pass 不再运行；
    - **泛光** 开 / 关：泛光强度置 0（后处理跳过泛光 pass，调色保留）；
    - **粒子效果** 开 / 关：CPU 与 GPU 粒子发射器；
    - **光照色阶** 跟随场景 / 平滑：平滑时光照级数置 0。
  - 每帧先应用房间观感（含渐变），再叠加玩家设置，所以房间之间的观感过渡不受影响。开发热键与开发面板仍是独立的临时开关，不写入设置：效果在玩家设置与开发开关都打开时才开；F4 选“跟随观感”时服从玩家的光照色阶设置。
  - 测试运行（`--deterministic`、`--demo`、`--data`、`--start-room`）不读用户的设置文件，渲染回归始终使用默认值；需要时用 `--settings` 指定。
- 主要理由：只调已有的观感与渲染参数，不新增渲染路径；保存在已有的设置文件中，沿用其容错（越界值被夹紧、类型不对的项用默认值）。
- 验证方式：设置的单元测试（往返、亮度夹紧、类型错误回退默认）；菜单测试 `menu_graphics` 像玩家一样进入图形页修改各项并检查结果；默认设置下渲染回归与基准图逐像素相同；用 `--settings` 分别截图确认每项都改变画面（亮度 130% / 70% 时平均亮度约 +37% / −38%，关闭补光约 −23%）。
- 代价与风险：亮度只是曝光倍数，暗部提亮有限，过高时亮部更早饱和；关闭补光后画面回到 ADR-0039 之前偏暗的样子。
- 重新评估条件：需要画质预设、伽马曲线或按房间的玩家覆盖时，在同一设置段中扩展。
