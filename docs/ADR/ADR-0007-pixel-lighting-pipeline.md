# ADR-0007: 像素光照管线

- 状态：Accepted
- 日期：2026-10-22
- 背景与问题：V1 视觉样板的第一项是像素光照：点光源照亮带法线贴图的场景、自发光、暗部过渡，且必须保持像素风格的清晰边缘，并在 OpenGL 与 Vulkan 上输出一致。
- 备选方案：
  - 在窗口分辨率做光照（平滑但破坏像素感）；在 320×180 画布分辨率做光照。
  - 前向渲染（每个精灵在着色器里循环所有光源）；延迟渲染（先写 G-buffer，再逐光源累积）。
- 决策：**在画布分辨率做延迟光照**，三个 pass：

| Pass | 输出 | 内容 |
|---|---|---|
| 材质 pass | albedo RGBA8、normal RGBA8、emissive RGBA8（多颜色附件） | 精灵按材质（albedo + 法线 + 自发光三张图）绘制，三个输出都按覆盖率预乘后混合。清除值：albedo = 背景色，normal = 平面法线 (0.5, 0.5, 1, 0)，emissive = 0。 |
| 光照 pass | light RGBA16F | 每个点光源一个方块，加色混合（One, One）。Lambert 漫反射 × (1 − d/r)² 衰减；光源有“高度”，高度越低越贴近表面、法线起伏越明显。 |
| 合成 pass | 画布 RGBA8 | `albedo × (ambient + light) + emissive`；可选把光照强度量化为 N 级（按最大分量缩放以免偏色）并加 4×4 有序抖动；再混入被同一光照照亮的烟（ADR-0008）。 |

- 约定：
  - 法线编码 `rgb = n × 0.5 + 0.5`，+x 向右、+y 向下（与画布一致）、+z 指向屏幕外；水平翻转的精灵由着色器根据 `dFdx(u) < 0` 自动镜像法线。
  - 光照与合成 pass 由裁剪坐标计算屏幕 uv（RHI 约定 NDC (−1, −1) 为左上角纹素），不使用 `gl_FragCoord`，保证两后端一致。
  - 光源、环境光与量化参数是游戏每帧提供的数据（`PointLight`、`LightingSettings`）；渲染器不保存光源状态。
  - 发光粒子等“光源像素”在合成之后的发光 pass 中以加色混合叠加（不受光照影响）；需要照亮周围时另加点光源。
- 调试叠加（碰撞视图等）在合成之后的无光照 pass 中绘制。
- 主要理由：画布分辨率光照天然保持像素颗粒感，成本与屏幕分辨率无关；延迟方式让光源数量与精灵数量解耦；量化 + 抖动给出像素风的明暗台阶。
- 代价与风险：没有阴影遮挡（光会穿过墙壁）；半透明精灵的法线 / 自发光按覆盖率混合，是近似；RGBA8 自发光不支持超过 1 的亮度（泛光阶段再评估）。
- 影响的模块：RHI（新增 RGBA16_Float、OpenGL 多颜色附件）、renderer（Renderer2D、SpriteBatch、LightingPass）、shaders、美术规范（docs/ART_PIPELINE.md）。
- 验证方式：演示房间在两后端逐像素一致（含抖动，容差 0），Vulkan 验证层（含同步验证）零报错；`--deterministic` 保证截图可复现。性能（macOS / Apple M2，Release）：OpenGL 完整一帧约 0.9 ms；Vulkan 窗口模式受合成器限制，帧率封顶在显示器刷新率（120 Hz），阻塞发生在呈现阶段而不是帧内工作。
- 重新评估条件：需要阴影 / 遮挡、大量光源导致光照 pass 成为瓶颈、或泛光需要 HDR 自发光时。
