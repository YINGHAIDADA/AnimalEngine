# ADR-0018: 水

- 状态：Accepted
- 日期：2026-10-23
- 背景与问题：M3 的“水面与更多流体类型”。需要可在 Tiled 中摆放的水域，水面会被角色搅动，角色在水中的运动有变化（已选定：减速 + 浮力，可跳出水面，不做自由游泳），渲染保持像素风且两后端逐像素一致，OpenGL 4.1 下用片元着色器实现。
- 决策：
  - **水面模拟**（框架 `WaterBody`）：矩形水域，顶边为静止水面；每个像素列一个位移与速度，按一维波动方程推进（`waveSpeed` 90 px/s、回复 `stiffness`、阻尼 `damping`，位移限制在 ±6 px），按 `waveSpeed · dt ≤ 0.5 列` 自动分子步保证稳定。`disturb(x, 半宽, 速度)` 给附近的列加速度（中心最强），`surfaceY(x)` 与 `submersion(碰撞框)`（碰撞框中心列水面以下的高度占比）供游戏使用。
  - **漂浮**（框架 `swimmingParams` / `applyWater`）：按淹没比例 s 改写平台跳跃参数——重力乘以 `1 − s / floatDepth`（`floatDepth` 0.6，更深时变为浮力）、取消下落加重，奔跑速度 / 加速度与最大下沉速度按 s 插值缩小；每步对速度施加 `drag · s` 的水阻；s ≥ 0.3 时允许起跳（用 coyote 计时实现），从而可以跳出水面。`stepPlatformer` 本身不变。
  - **溅水**（游戏）：角色碰撞框穿过水面时（入水，或带向上速度出水）在入点扰动水面，并按 `effect` 属性触发溅水粒子预设（缺省 `splash.effect.json`，ADR-0017）；贴着水面横向移动时在前方推出小波。
  - **渲染**（`Renderer2D::addWater` + 水 pass）：
    - 游戏每帧提交 `WaterSurface`（位置、宽、深、每列位移、颜色、浓度、倒影、折射像素数、动画时间）。渲染器把每列的“水面行 / 水底行 / 样式”写成一行 RGBA8（320×1，整行坐标，CPU 上取整），最多 4 种样式；同一列只画最后一个水体。
    - 有水时，光照合成改写到 `lit` 目标，水 pass（全屏）读取 `lit` 与光照缓冲写入 canvas；没有水的房间不运行水 pass、也不多一次拷贝。
    - 水面以下的像素：按 `(行 + 相位) & 7` 查一张整数表做阶梯状横向晃动（折射）；与“水色 × (环境光 + 该像素的光照)”按浓度混合，浓度随深度增加（每像素 +0.015，最多 0.92）；上部混入以水面为轴的镜像（倒影，16 px 内淡出）；水面那一行提亮；浓度与倒影强度按光照级数量化抖动。动画相位 = `floor(时间 × 8)`。
    - 选择“读哪个像素”只用整数（列数据、晃动表、镜像行），两后端逐像素一致。
  - **Tiled**：`water` 矩形对象；属性 `color`、`opacity`、`reflection`、`refraction`（int）、`effect`（溅水预设）。示例：烟雾深坑地面右侧挖出 10 格宽、16 px 深的水池（两侧两格高的岸），上方挂一盏灯具照亮水面与倒影。
- 主要理由：一维表面波是 2D 像素游戏的标准做法，开销极小且确定；漂浮规则以“改写参数”的方式叠加在现有平台跳跃上，不需要第二套移动逻辑；水 pass 只在有水时运行，读取合成后的画面，所以折射、倒影天然包含角色与光照。
- 代价与风险：同一列只支持一个水体；水不遮挡光、不与烟雾流体耦合；发光粒子在水 pass 之后绘制，不被折射；只有角色与水互动（甲虫、粒子不会溅水）；没有水下的光照衰减（只靠浓度随深度变暗）。
- 验证方式：water 测试覆盖静止不动、扰动传播 30 px 后衰减、位移上限、淹没比例、从空中落入水池后漂浮在 0.3–0.9 淹没之间且不触底、起跳能离开水面、漂浮参数随深度变化；临时把角色放在水池上方落下，截图确认溅水粒子、水面凹陷与波、水下折射与倒影、最终半浮于水面；两后端截图（含水池场景）逐像素一致，验证层零报错；水 pass 约 0.04 ms（Vulkan，Release）。
- 重新评估条件：需要瀑布 / 流动的水、多层水体、水下光照与焦散、或其他实体与水互动时。
