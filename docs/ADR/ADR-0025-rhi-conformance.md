# ADR-0025: RHI 功能一致性测试

- 状态：Accepted
- 日期：2026-10-23
- 背景与问题：M2.5 要求补齐“只在 OpenGL 实现的 RHI 功能”。审计结果：M1–M3 每一步都同时实现了两个后端，没有缺失的功能；但渲染器只用到 RHI 的一部分，三角形条带、线段、剔除与正面朝向、重复寻址、线性过滤、Subtract / ReverseSubtract / Min / Max 等混合、实例步进的顶点属性、Float3 属性、R8 / RGBA16F / RGBA32F 纹理上传、局部纹理更新、带偏移的 uniform 绑定、跨通道 LoadOp::Load 从未被执行，渲染回归覆盖不到——将来第一次用到时才会发现后端差异。
- 决策：
  - 新增工具 `animal_rhi_conformance`（`tools/rhi_conformance/`，输出 `AnimalRhiConformance`）：不经过游戏框架，直接用 RHI 在 256×128 离屏目标上为每项功能画一个 32×32 格子（4 行，见源文件开头的表），再用多渲染目标写第二个目标，读回两者并排存为 PNG。
  - 渲染回归脚本把它作为第 7 个场景：两后端逐像素相同、与 `tests/golden/rhi_conformance.png` 相同、Vulkan 验证层与 RHI 校验零报错。
  - 审计中发现并统一的差异：MoltenVK 无法关闭三角形条带的图元重启（OpenGL 默认关闭），Vulkan 后端对条带改为开启重启，RHI 约定“索引条带不得使用最大索引值”，两后端行为因此一致。
- 主要理由：一致性必须由执行来证明，而不是阅读代码；一个固定的功能图既能发现后端差异，也能在重构后端（拆分、屏障、内存）时作为回归保护。
- 代价与风险：线段光栅化在不同厂商驱动上可能有合法差异（当前 Apple M2 上两后端相同），在 Windows 上若出现差异需按厂商调整容差或改用三角形；新 RHI 功能需要同时在工具中加格子。
- 验证方式：截图逐格核对（三角形、条带、三种线段；背面 / 正面剔除各保留正确的三角形；4 个实例；uniform 偏移得到橙色；最近邻 / 重复 / 线性 / 越界夹取；R8 红色阶、RGBA16F、RGBA32F、局部上传的红块；七种混合结果与公式一致；第二目标为反色；跨通道 Load 后两个三角形都在）；两后端逐像素一致，零报错。
- 重新评估条件：新增 RHI 功能（计算、深度、mip、数组纹理、存储缓冲）时扩展格子。
