# ADR-0006: 房间尺寸、坐标单位与移动碰撞模型

- 状态：Accepted
- 日期：2026-10-22
- 背景与问题：PROJECT.md v1.2 确定了单屏房间、8 px Tile、出屏切换。M1a 需要确定房间的确切尺寸、世界坐标单位，以及角色移动与碰撞的计算方式；这些会影响所有关卡数据和手感参数。
- 备选方案：
  - 房间高度：22 Tile（176 px，余 4 px）；23 Tile（184 px，超出画布 4 px）；画布改为 320×176。
  - 移动：浮点位置 + 扫掠 AABB；整数像素位置 + 小数余量逐像素移动（Celeste 式）；完整物理引擎。
- 决策：
  - **房间 40×22 Tile = 320×176 px**，在 320×180 画布中垂直居中，上下各留 2 px 边框（以后可用作 HUD 区域）。相机对每个房间固定，不跟随角色。
  - **世界单位 = 像素**；速度单位 px/s，加速度 px/s²；模拟固定 60 Hz（Application 已保证）。
  - **整数像素位置 + 小数余量**：每步把 `速度 × dt` 加到余量上，取整后一次移动 1 px 并检测碰撞，碰到就停。先移动 X 再移动 Y。
  - 碰撞体是相对实体位置的整数矩形；Tile 的“实心”属性由 Tile 类型表决定。
  - 实体用 `EntityId`（代际句柄）引用，存放在扁平数组中；组件不做通用 ECS，按需加字段。
- 主要理由：整数位置让渲染、碰撞和关卡数据都在同一个像素网格上，不会出现亚像素抖动；逐像素移动在任何速度下都不会穿墙，边界情况（贴墙、落地、墙角）的结果确定，容易写单元测试；固定步长下行为可复现。
- 代价与风险：逐像素移动在极高速度下循环次数多（对 2D 平台游戏的速度量级可以忽略）；斜坡需要另行处理（暂不支持）。
- 影响的模块：framework（Tile 地图、物理、实体）、game、后续 Tiled 关卡格式（M1b）。
- 验证方式：framework 单元测试覆盖贴墙停止、余量累积、高速不穿墙、落地、1 Tile 通道、coyote time、跳跃缓冲、可变跳高、天花板角修正。
- 重新评估条件：需要斜坡、移动平台推动或大量物理对象时。
