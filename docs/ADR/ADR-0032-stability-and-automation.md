# ADR-0032: 稳定性与自动化验证（无头运行、存档健壮性、CPU 分析、崩溃诊断）

- 状态：Accepted
- 日期：2026-10-23
- 背景与问题：M6 要求“从启动到通关一段完整区域无需开发者手动修补；干净构建可重复；已知问题有清单”。此前游戏只能开窗口运行，CI 只跑单元测试，无法验证整段游玩；存档只有一份文件，写坏或被新版本写过就会丢进度；CPU 一侧没有分区计时，只有 GPU pass 的耗时（ADR-0016）；崩溃时除了终端输出什么都不留下，玩家机器上的问题无法追查。
- 决策：
  - **无头运行**（`--headless`）：RHI 增加 `Backend::Null`（`engine/src/rhi/null`）——接受全部资源创建与命令录制、不做任何绘制，能力与 OpenGL 后端一致；不创建窗口，模拟、关卡、实体、粒子、音频状态照常运行。配合 `--deterministic --demo` 在约 1 秒内跑完演示路线，不需要 GPU，CI 的所有构建都能运行。
  - **预期检查**（`--expect=room:NAME,gems:N,visited:N,grounded:true,respawns:N`）：退出时由游戏检查，逐项写日志，未满足时退出码为 3；`--strict` 让 RHI 校验层的任何错误使运行失败（退出码 4）；`EngineContext::exitCode` 让游戏报告失败。ctest `demo_playthrough`：无头、确定性、严格模式跑完演示，要求到达烟雾深坑、拾取 2 颗宝石、进入 3 个房间、没有掉出世界。
  - **存档版本 2**（`framework/save.h`）：增加已访问房间（地图）与游戏时间；版本 1 自动迁移（继续所在的房间算作已访问）。写入前把当前**有效**的存档保留为 `.bak`，再原子写入（临时文件 + 重命名）。读取结果分五种：没有存档、正常、损坏但从备份恢复（损坏的文件改名为 `.corrupt` 保留）、来自更新的版本（不读也**不覆盖**，提示玩家）、存档与备份都损坏（保留为 `.corrupt`，开始新游戏）。退出游戏时也保存（游戏时间与已访问房间，位置仍是最后的检查点）。
  - **CPU 分区计时**（`core/profiler.h`）：`ANIMAL_PROFILE_ZONE("名称")` 计时到作用域结束，可嵌套，同一帧多次进入（每个固定步一次）累加。应用标记帧边界；分区覆盖事件、更新、模拟（玩家 / 房间 → 水、生物、植物、藤蔓、粒子）、取交换链图像、渲染、提交、呈现、开发工具。性能面板显示每个分区的历史曲线，`--profile` 在退出时打印各分区的平均 / 最大耗时。只在主线程使用，开销是每个分区两次计时器读取。
  - **日志文件**：`<用户数据目录>/logs/<应用>.log`，每次启动轮转，保留最近 5 份；警告与错误立即刷新到磁盘。
  - **崩溃报告**：启动时最先安装（`platform::installCrashHandler`，`AppConfig::applicationId` 决定目录），在 `<用户数据目录>/crashes/` 写 `crash-<时间>-<序号>.txt`：原因、地址、日志文件位置与调用栈。macOS 处理致命信号（SIGSEGV / SIGBUS / SIGILL / SIGFPE / SIGABRT / SIGTRAP，使用备用信号栈，栈溢出也能报告），报告后恢复默认动作再次发出信号；Windows 用未处理异常过滤器写报告并生成 minidump（`.dmp`），`abort()` 不弹对话框；未捕获的 C++ 异常经 `std::set_terminate` 记录异常信息。报告路径在启动时准备好，崩溃时不分配内存。`--crash-test=segv|abort|exception` 故意崩溃，`--crash-dir` 改变报告目录；ctest `crash_report_*` 在两个平台上检查三种崩溃都留下完整报告。
- 主要理由：无头后端让“整段游玩”与单元测试一样便宜，CI 每次提交都能验证；预期检查放在游戏里，测试只描述结果，不依赖帧号；存档只保留上一份有效版本，简单且足以应对写入中断与文件损坏；分区计时与 GPU 计时并列，性能问题能先定位到 CPU 还是 GPU；崩溃报告是纯文本，玩家可以直接附在问题报告里。
- 结果（Apple M2）：无头演示 900 帧约 1 秒（Release）；演示路线上每帧模拟约 0.16 ms（藤蔓最贵）；三种崩溃在 macOS 与 Windows CI 上都生成完整报告。
- 代价与风险：Null 后端不验证绘制结果（画面仍由渲染回归覆盖）；信号处理中的 `backtrace_symbols_fd` 并非严格异步信号安全，是常见折中；macOS 只有符号化的调用栈，没有 minidump；存档备份只有一代。
- 验证方式：单元测试（存档往返、迁移、损坏恢复、新版本拒绝、备份；分析器嵌套与累加）；ctest `demo_playthrough` 与 `crash_report_{segv,abort,exception}`；CI 六个构建（macOS / Windows × Debug / Release / 无开发工具）全部运行。
- 重新评估条件：需要上传崩溃报告、符号服务器或多线程分析时，接入外部工具（如 Tracy / Crashpad）；存档内容变复杂时改为多存档位。
