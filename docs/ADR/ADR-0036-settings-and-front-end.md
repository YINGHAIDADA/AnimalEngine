# ADR-0036: 设置、显示、输入与游戏前端

- 状态：Accepted
- 日期：2026-10-24
- 背景与问题：M7 要求发行版在玩家的机器上独立运行，包括窗口 / 全屏、高 DPI、音频设备变化、输入映射与控制器。此前窗口大小写死为 1280×720，垂直同步只能在启动时决定，没有全屏，按键不可更改，没有标题与暂停菜单（Escape 直接退出），音频设备只在启动时打开。
- 决策：
  - **设置文件**（`framework/settings.h`）：`<用户数据目录>/settings.json`，版本化 JSON、原子写入；音量（总 / 音效 / 环境 / 音乐）、全屏、窗口大小与位置、垂直同步、帧率上限（无 / 30 / 60 / 120 / 144）、玩家改过的按键。超出范围的值被截断、不认识的输入被丢弃、文件损坏时用默认值——设置永远不会让游戏起不来。内容有变化才写入（菜单关闭时与退出时）。测试运行不读写真实的设置文件（`--settings=路径` 可指定）。
  - **窗口与显示**：默认窗口取能放进主显示器 85% 的最大 320×180 整数倍；保存的位置若已不在任何显示器上（拔掉了副屏）则居中；无边框全屏，退出全屏回到原来的窗口位置（F11 / Alt+Enter）；高 DPI 由 SDL 的高像素密度窗口提供，渲染按像素尺寸进行。`Device::setVsync` 让三个后端在运行中切换垂直同步（Vulkan 以新的呈现模式重建交换链）；关闭垂直同步时主循环按 `EngineContext::frameCap` 精确睡眠。
  - **音频设备变化**：以系统默认设备打开的音频流由 SDL 自动迁移到新的默认设备（默认设备消失时暂挂，出现后继续）；引擎补上“启动时没有设备、之后插上”的情况，并在日志中记录正在使用的设备。单元测试经 SDL 的 dummy 驱动覆盖设备路径。
  - **输入**：游戏动作有名称与默认绑定（键、手柄按键、摇杆方向）；设置中的按键与手柄按键替换默认值（摇杆保留）。`Input::lastDevice` 判断最近使用的设备，提示文字随之显示键名或按手柄类型显示按键（A / CROSS / B，LB / L1 / L，MENU / OPTIONS / +）。手柄热插拔沿用已有处理，拔掉后提示回到键盘。
  - **游戏前端**（`game/src/front_end.cpp`）：标题（继续 / 新游戏，有存档时需确认 / 设置 / 退出），背景是仍在运动的房间；暂停菜单（继续 / 设置 / 回到标题）冻结世界；设置页：音频、显示（开垂直同步时帧率上限不可选）、按键（按下新键即绑定，并从其他动作上移除；恢复默认）。菜单导航使用固定输入（方向键 / WASD / 十字键 / 摇杆，Enter / 空格 / 南键确认，Escape / 退格 / 东键返回），改键不会把玩家锁在菜单外。通关画面之后回到标题；Escape 改为暂停。
  - **测试**：测试运行默认跳过标题；`--title` 从标题开始，`--menus` 启用菜单但直接开始游戏；`--expect=screen:页面`、`setting:名称:值`。菜单测试：新游戏、暂停回标题、调音量、关垂直同步并设帧率上限、改键、通关回标题；能力测试：设置文件中改过的键生效、默认键不再生效。
- 主要理由：设置与存档一样走原子写入和宽容解析，玩家的文件出问题时游戏照常启动；音频设备迁移交给 SDL，引擎只补缺口；菜单用固定导航、每帧重建菜单项，状态简单且标签永远是最新的。
- 代价与风险：手柄只在键盘映射层面验证，真机（Xbox / PlayStation / Switch Pro）与 Windows 混合 DPI 需要在目标机器上确认；改键只换每个设备的第一个输入（每个动作在每种设备上一个键）；暂停 / 标题菜单的文字使用调试字体。
- 验证方式：单元测试（设置往返、截断与丢弃、损坏回退；手柄按键名称；dummy 驱动播放）；ctest `menu_*`、`capability_rebound_*`；手动：F11 进出全屏后保存的位置、移出屏幕的位置被居中、帧率上限 30 时 120 帧约 4 秒。
- 重新评估条件：需要多个存档位、语言切换或手柄震动时扩展设置格式（带版本号）。
