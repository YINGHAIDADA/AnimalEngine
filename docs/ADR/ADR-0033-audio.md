# ADR-0033: 音频（SDL3 设备 + 自有混音器 + WAV / Ogg Vorbis）

- 状态：Accepted
- 日期：2026-10-23
- 背景与问题：M6 的纵向切片需要音效与环境声。需求很小：几十个同时发声的短音效、循环的环境声，后续有音乐；要有音量分组（音效 / 环境 / 音乐）、左右声像、淡入淡出；资源要能热重载、能进资源包（ADR-0031）；无头运行与测试中不能依赖音频设备。PROJECT.md 把音频格式列为待定问题。
- 决策：
  - **设备**：SDL3 音频流（`SDL_OpenAudioDeviceStream`），48 kHz、立体声、32 位浮点。SDL 在自己的线程中回调，混音器按需填充。没有设备（`--mute`、`--headless`、测试，或打开失败）时同样工作，只是不输出；`mix()` 可直接调用，测试据此逐样本检查。
  - **混音器**（`engine/include/animal/audio/audio.h`，`audio::AudioSystem`）：自己实现，约 400 行。32 个声部（固定数组 + 代数句柄，过期句柄无效）；每个声部有音量、声像（平衡式）、播放速率（线性插值，用于音高变化）、循环、所属分组与淡入 / 淡出；分组音量与主音量；输出经过软限幅，多个声音叠加也不削波。声部用满时让最安静的声部让位。游戏线程与音频线程之间用一把互斥锁，每次调用只做很少的工作。
  - **格式**：WAV 由 SDL 解码，Ogg Vorbis 由 stb_vorbis（v1.22，单独的 C 库，不带项目警告编译）解码；载入时一律用 `SDL_ConvertAudioSamples` 转为 48 kHz 立体声浮点，混音时不再重采样。`decodeSound` 也被烘焙工具用来校验。
  - **资源**：源文件在 `assets/source/sounds/`，构建时部署到 `data/sounds/`；`assets/cook.json` 的 `"sounds"` 列表决定打包哪些音效，烘焙前后各解码一次校验（当前原样存储，由包的 zstd 压缩）。热重载：保存音效文件后 `reload()` 替换解码后的数据，正在播放的声部继续使用旧数据直到结束。
  - **游戏接入**：`EngineContext::audio` 由 Application 拥有。跳跃、落地（音量随落地速度）、抓住藤蔓、宝石、被甲虫撞到、入水的音效按画面位置设置声像，音高在 ±5% 内随机——随机数来自单独的生成器，不影响模拟的确定性；入口的洞穴环境声在环境分组上循环并淡入。分组音量在参数表中（`audio.effects` / `audio.ambience` / `audio.music`）。性能面板显示声部数、已载入的音效数与输出峰值。
  - **占位音效**：`tools/scripts/make_placeholder_audio.py` 确定性地合成 7 个 22.05 kHz 单声道 WAV（同样的脚本得到逐字节相同的文件），之后由正式音效替换，文件名不变即可。
- 主要理由：需求简单到一个小混音器就能完全掌控（确定性、无设备运行、测试），不必引入 FMOD / Wwise 这类中间件或 miniaudio 这样的完整库；SDL3 已是平台层，设备与格式转换都由它处理；Ogg Vorbis 无专利、压缩率好，stb_vorbis 是单文件依赖。
- 结果（Apple M2，Release）：32 个声部同时循环时混音约占一个核心的 1.2%；演示路线播放 10 次声音（环境声、跳跃、落地、宝石）；资源包从 48.8 KB 增加到约 337 KB，其中占位音效约 296 KB（环境声是 6 秒未压缩 WAV，换成 Ogg 会小很多）。
- 代价与风险：没有效果器（混响、滤波）与流式播放，长音乐会整首解码进内存（48 kHz 立体声浮点每分钟约 23 MB）；线性插值变速在大幅变调时有混叠；混音器的锁在游戏线程调用很频繁时可能让音频线程等待（当前每帧只有几次调用）。
- 验证方式：单元测试（WAV 解码与重采样到输出采样率；音量、声像、分组、声部结束；淡入淡出、限幅、声部抢占；损坏数据被拒绝）；烘焙测试检查音效进入资源包并通过校验；演示运行在有设备与无头两种情况下都能播放并通过预期检查。
- 重新评估条件：加入音乐时增加 Ogg 流式解码（按块解码到环形缓冲）；需要空间混响或大量声音时考虑 miniaudio 的节点图或中间件。
