# ADR-0009: 泛光与调色

- 状态：Accepted
- 日期：2026-10-22
- 背景与问题：V1 最后一项：发光物体（火焰、水晶、萤火虫）周围的光晕和整体色调，同时保持像素风格，不能变成一层平滑的雾。
- 备选方案：
  - 泛光来源：只用自发光 / 发光粒子；对最终画面按亮度阈值提取。
  - 泛光外观：平滑叠加；量化 + 有序抖动叠加。
- 决策：
  - **后处理 pass** 位于光照合成、烟雾与发光粒子之后，写入独立的最终画布；屏幕 pass 显示最终画布，调试叠加画在最终画布上（不受调色影响）。
  - **泛光**：对画布按最大通道亮度提取（阈值 + 柔和过渡），降采样到 160×90（线性采样平均 2×2），做两轮 9-tap 可分离高斯模糊；加回时按 N 级量化并用与光照相同的 4×4 有序抖动，使光晕呈像素台阶。
  - **调色**（同一 pass）：曝光 → 暗部 / 亮部分别乘色调（按亮度插值）→ 饱和度 → 以中灰为支点的对比度 → 暗角。全部参数在 `PostSettings`，默认中性（除泛光外无变化），`enabled = false` 时原样复制画布。
  - 泛光贴图首次使用时清零（新建的 Vulkan 图像可能含 NaN，权重为 0 也会传播）。
- 主要理由：阈值提取对所有亮物体一视同仁，无需额外缓冲；降采样 + 量化抖动既有柔和光晕又保持像素感；调色集中在一处，便于按房间或场景调整。
- 代价与风险：阈值提取会让被照得很亮的普通表面也泛光（通过阈值控制）；对比度以中灰为支点，在暗场景中会整体压暗——演示房间用曝光补偿（平均亮度：关闭 11.3，补偿后 9.4）。
- 验证方式：演示房间开启后处理，OpenGL 与 Vulkan 截图逐像素一致（容差 0），Vulkan 验证层零报错；性能（Apple M2，Release，OpenGL）完整 V1 场景约 2.3 ms / 帧，泛光与调色的额外开销可忽略。
- 重新评估条件：需要按区域或时间变化的调色（LUT）、HDR 自发光，或泛光需要只来自特定物体时。
