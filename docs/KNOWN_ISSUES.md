# 已知问题

M6 验收要求“已知问题有清单”。这里列出当前版本中已知、但有意未处理（或留给后续里程碑）的问题；修复后从清单中删除并在提交信息中注明。

## 内容与表现

| 问题 | 影响 | 处理方向 |
|---|---|---|
| 美术与音效全部是占位资源（`tools/scripts/make_placeholder_art.py`、`make_placeholder_audio.py` 生成） | 观感简陋；环境声是 6 秒未压缩 WAV，占资源包约 300 KB 中的大部分 | 同名替换为正式资源；长音频改用 Ogg Vorbis |
| 淹没的房间（地下湖、沉没神殿、暗流、淹没隧道）对比度低，墙与背景都是砖纹，水面线画在房间顶边 | 水下路线不如地面直观 | 水下专用 Tile 与背景、整间房间是水时不画水面线 |
| 下潜复用攀爬动画 | 动作不够贴切 | 增加游泳动画标签（`swim`） |
| 新增 12 颗宝石中，录制路线时实际拾取过的是断桥的 2 颗；其余按布局与跳跃能力核对过（自动测试不再检查内容，ADR-0035） | 个别宝石可能需要比预想更精确的操作 | 试玩 |
| 地图画出已访问房间的地形、门与开关（及其状态）、宝石与玩家，但不画移动 / 坠落平台 | 平台位置要靠记忆 | 地图上画出平台的路径 |

## 玩法与系统

| 问题 | 影响 | 处理方向 |
|---|---|---|
| 没有下潜能力时，整间是水的房间里角色会站在水底行走（只能经 `--start-room` 到达，正常游玩进不去） | 仅测试时可见 | 无需处理，或改为一律上浮 |
| 向上穿过房间边界需要关卡配合（上方房间底边旁的落脚点、或连通的水） | 设计新房间时容易做出上不去的出口 | 关卡编辑器中提示向上出口；或加入向上过渡时的助推 |
| 坠落平台回到原位时若玩家站在那里会一直等待 | 玩家站在原位时平台不出现 | 可接受；必要时改为稍后重试的同时给出提示 |
| 平台只携带 / 推动玩家；甲虫与粒子不随平台移动 | 甲虫不要放在平台上 | 需要时把实体加入携带列表 |
| 血量不进存档，也没有回血道具；只有血掉光时才回满 | 重新启动游戏即满血 | 加入回血拾取物或在检查点回血时一并存档 |
| 携带的炸药不进存档，拾取物在重新进入房间时会再出现 | 炸药可以反复拾取（最多 9 个） | 需要稀缺时改为存档标志 |
| 爆炸不伤玩家、不破坏地形；冲击波对草与藤蔓是三个固定方向的推力 | — | 可破坏的墙、会伤人的爆炸（ADR-0038） |
| 手柄只在键盘映射层面验证，未在真机上测试（Xbox / PlayStation / Switch Pro 的按键标签按 SDL 的类型判断） | 手柄手感与按键提示未经确认 | 真机验证（M7 第八步） |
| 改键每个动作在每种设备上只保留一个输入 | 不能同时把跳跃绑在空格和 Z 上（默认绑定除外） | 需要时在按键页支持追加 |

## 发行（M7）

| 问题 | 影响 | 处理方向 |
|---|---|---|
| macOS 发行版只带 OpenGL：没有随包附带 Vulkan 加载器与 MoltenVK | 发行版选择 Vulkan 后端会失败 | 打包时附带 `libvulkan` 与 MoltenVK |
| 只构建本机架构，没有 arm64 + x86_64 通用二进制 | Intel Mac 无法运行 CI 产出的 macOS 包 | `CMAKE_OSX_ARCHITECTURES="arm64;x86_64"` 打包 |
| 只有 ad-hoc 签名，未公证；Windows 未签名 | 首次打开会被 Gatekeeper / SmartScreen 拦截 | 第八步：Developer ID 签名与公证、Windows 代码签名 |
| 启动失败的错误对话框没有自动化验证（模态窗口） | — | 目标机器上目视确认 |
| Windows 混合 DPI、多显示器只在 macOS 上验证过对应逻辑 | — | Windows 目标机器验证 |
| 菜单与标题使用调试字体 | 观感简陋 | 正式字体 |

## 引擎与工具

| 问题 | 影响 | 处理方向 |
|---|---|---|
| 音频没有流式播放与效果器（混响、滤波）；长音乐会整首解码进内存 | 目前没有音乐，暂无影响 | 加入音乐时实现 Ogg 流式解码（ADR-0033） |
| macOS 崩溃报告只有符号化的调用栈，没有 minidump；信号处理中的 `backtrace_symbols_fd` 并非严格异步信号安全 | 极端情况下报告可能不完整 | 需要时接入 Crashpad 一类的工具（ADR-0032） |
| 存档只保留一代备份 | 连续两次写坏才会丢进度 | 多存档位时一并处理 |
| Null 后端不验证绘制结果 | 无头测试只覆盖逻辑，画面靠渲染回归 | 保持渲染回归在开发机上运行 |
| 测试数据（`tests/data`）是内容的一份副本，贴图与预设不随游戏美术更新 | 渲染回归验证的是渲染器，不是当前美术 | 新增引擎能力时在测试房间中覆盖（ADR-0035） |
